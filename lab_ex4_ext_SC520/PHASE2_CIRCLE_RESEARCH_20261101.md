## 1. 失败原型归因（只读 `isp_grad_hough.v` / HOUGH 报告）

- 最终源码综合：ERAM **122/108**、DSP **50/40**、slice **125.65%**、
  setup **−3.803 ns**（757 违例端点）；`u_grad_hough` 单独 **95 ERAM /
  26 DSP**、3,438 logic LUT、1,544 seq。
- 存储主项：
  - 全分辨率 1bit 边缘图 `emap` 28,800×32b（约 922Kb）；
  - 4×4 方向图 `dmap` 3,600×32b（约 115Kb）；
  - 16px 中心网格 80×45×3 档 8bit 累加器（约 86Kb）；
  - 512×32b 事件 FIFO、3×320×32b 行缓存。
- 最差路径（gate.timing）：
  - `S_cand_i_reg[4]` → `S_vcx_reg[0]`，−3.803 ns；
  - `S_top_sc_reg[71]` → `S_top_x_reg[0].ce`，−3.552 ns。
  即 **top-K/候选扫描/精验选择**的长组合链，不是前端 Sobel；且 103.5MHz
  单周期完成这些大 mux/比较。
- 功能边界：r25 全拒绝、r26 在 (402,363) 相位失败；可靠半径约 58px；
  4×4 棋盘误报；小圆+大椭圆、矩形+圆竞争失败。

**结论**：不能沿用“全分辨率精验图 + 16px 网格 3 档 + top-K 大 mux”的架构；
必须去掉全分辨率边缘缓存、把半径验证改成低存储的 1D 直方图/流式，
并把 top-K/评分拆成多周期、流水化。

## 3. 候选架构：去全分辨率缓存的“中心投票 + 径向直方图”

### 3.1 事件前端（4×4 块，1 事件/块）

- 从 `O_dg_y4` 取 4 像素/拍；`[31:24]=x+0`，`[7:0]=x+3`。
- 真实有符号 1×1 Sobel：只用每拍中间两个像素（x+1、x+2）的完整 3×3
  窗口，**不是**水平 2 像素平均；每 4×4 块在 4 行内选最强梯度，
  块内位置编码到 1px（subx=1/2，suby=0..3）。
- **方向必须 8-bit（256 档）**：模型实测 6-bit（64 档）只有 10/20
  圆例通过且圆 vs 矩形失败；8-bit 才能到 16/20 + 竞争全过。
  前端用有符号 Gx/Gy 的 CORDIC/atan2 产生 `ux,uy` Q8；不是 16 档常量表。
- 事件字：`x[11:0] y[11:0] ux[9:0] uy[9:0] sector[3:0]`（48b），
  `ux,uy` 是 Q8（256=1.0），含 +g/−g 极性。
- 行缓存 2×320×32b（约 20Kb），块累加器 320×16b（约 5Kb），
  事件缓存 2048×48b（约 98Kb）。预计 **5–8 ERAM**（与中心累加器分开）。

### 3.2 中心投票（帧内捕获，帧尾后处理）

- 2D 中心累加器 **4px 网格 320×180×8b = 460,800b**（约 23–29 ERAM）。
- 每个事件沿法线 ± 两个方向，从 r=26..160 以 8px 步进投票；
  Q8 方向用 1/256px 增量加法，**无乘法**；20 步 ×2 极性 = 40 票/事件。
- 事件上限 **2048/帧**：超过即 `ovf`，本帧直接拒绝；这同时是
  “密集纹理不框”的硬门控，避免 57,600 事件的最坏吞吐。
- 2048 事件 × 40 票 = 82K 票；1 票/cycle 的 2 拍 RMW 约 164K cycle。
- 帧尾/后处理扫描 57,600 cell，保留 top-6 中心（最小间距 NMS）；
  扫描 + 清零约 115K cycle（1 cell/cycle）。

### 3.3 细中心 + 径向验证 + 评分（同一帧事件后处理）

- **细中心是必需的**：模型用“只粗中心”时 r26/r60/r100 多相位大量失败。
  实现：把每条事件法线投影到粗中心附近，再在 ±16px 局部 33×33
  累加器里投票；每事件/候选 33 票。top-6、2048 事件 → 约 405K 票。
  投影 4 个乘法（可用 4 个或时分乘法器）。
- 径向直方图：r=26..160，1px 档，135 bins；对对齐事件
  （`|dot| >= 236*r`，Q8，含反极性）计票，并记录 16 扇区覆盖。
  6 候选 ×2048 事件 ×约 14 cycle ≈ 172K cycle。
- 评分：
  - `coverage`：峰值半径 ±2 内出现的 16 扇区数（≥10 才通过）；
  - `fill`：峰值 / 期望圆周块数（2πr/4，≈1.57r）；≥0.25；
  - `sharp`：峰值 / (峰值 + ±2 档)；只用于评分；
  - `align_frac`：对齐事件/总事件，**只作纹理门限（≥0.15），不进评分**；
    否则大圆会因自身事件多而天然占优（模型实测两圆 r40/r100 会偏向 r100）。
  - `score = coverage_norm * sharp * min(fill,1)`；**同分时选更小半径**，
    避免大圆票数偏置。
- 输出中心 = 细中心；半径 = 直方图峰值；bbox 由中心±半径并裁剪。
  无通过候选 → `valid=0`，不画框。

### 8.1 ERAM 推断的真实根因（已实测）

### 11.1 帧交接缺陷（已严格复现）

单事件 bank 下，每 2 帧捕获一次；被跳过的帧在“忙时开始”（cap_drop=1）。
旧逻辑在该帧 frame_end 时若 `proc_done` 已到（proc_busy=0），仍会为被丢弃帧

1. 捕获：`frame_end && !proc_busy && !cap_drop` 才启动处理；被丢弃帧不处理、
   不写结果、不产生 O_evt。
2. `S_IDLE` 在启动时先清 `best_ok/best_*`，空帧/溢出帧不再复用旧结果。
3. 有界保持 `HOLD=2`（处理帧）：有效检测刷新保持；**处理过的**无检测帧
   （空帧或 EVMAX 溢出）让保持减一，HOLD+1 个处理帧后清除；**被跳过的帧
   不老化保持**，只保持上一结果。

## 13. HUD 诊断修复与满载实测（2026-11-01 夜，rev 2i）

### 13.1 独立核对：原 HUD 为什么不能判定

1. **溢出与跳帧被合并**：`O_det_flags[7] = drop_seen | proc_drop | proc_ovf`。
   上板看到 [7]=1 时无法区分“事件数超过 EVMAX”和“整帧被跳过”。
   进一步核对发现 `proc_drop` 是死信号：被跳过的帧永远不会进入 `S_DONE`，
   所以任何一次结果里它都不可能为 1。
2. **计数截断/回绕且跨帧**：`O_det_cnt = S_ev_cnt[9:0]`。EVMAX=1536 时
   1536 → 512；1000..1023 在三位十进制 HUD 上会被错误解码。更严重的是
   `O_count_dbg` 在 `frame_end` 更新，而 flags/valid/bbox 在 `S_DONE` 更新，
   两者可能相差一整帧；wrapper 又在帧事件处整组取样，于是 HUD 可能显示
   “新帧的计数 + 旧帧的框/标志”。
3. **跳帧漏报**：旧 `drop_seen` 只在 `frame_end && proc_busy` 时置位。
   若某帧在 `frame_start` 时内核忙（`cap_drop=1`），但处理在该帧
   `frame_end` 之前就结束，这一帧实际被跳过却不会置位。
4. **处理时间估算错误**：12.4 节用“1002 事件 897k 周期”外推 1536 事件
   ≈1.37M 周期。实测当前 RTL 为 **≈1,526 周期/事件 + ≈246k 固定开销**，
   1536 事件需 **2,596,848 周期（1.50 帧）**，并不在一帧内完成。

### 13.2 修复（不改 valid/pass 语义）

- 新增 `isp_evt_hud_map.v`，EVT_CIRCLE=1 时 HUD 位布局显式改为：

| bit | EVT 含义 | 旧 EVT 含义 |
|---|---|---|
| [7] | `proc_ovf`：本处理帧事件数 > EVMAX（实际溢出） | drop/ovf 合并 |
| [6] | `live`：本处理帧计数 != 0（同一快照） | 帧尾计数 |
| [5] | `drop_seen`：自上一处理结果以来至少跳过一帧 | 0 |
| [4:2] | 0（CCL 的 chord/rows/asp/size 位置） | 0 |
| [1] | `pass`（不变） | pass |
| [0] | `valid`（不变） | valid |

- `O_det_cnt = min(事件数, 999)`：**饱和而非截断**。HUD 为三位十进制，
  比较器只覆盖 0..999，因此 999 表示“≥999”；满载 1536 显示 999，
  不再回绕成 512。检测器内部 `O_count_dbg` 仍为 12 位精确计数。
- `isp_circle_hough2`：`O_count_dbg` 改在 `S_DONE` 与

### 16.2 跟踪器 `isp_ball_track.v`

- **运动关联门限**（跟踪用）：与上一帧比，位置

### 18.1 音符 ROM 与频率

  120 BPM、64 半拍=16.0s：
  - C5 D5 E5 C5 ×2（各 1 拍）
  - E5 F5 G5(2 拍) ×2
  - G5 A5 G5 F5（各半拍）E5 C5（各 1 拍）×2
  - C5 G4（各 1 拍）C5(2 拍) ×2
- 方波频率 `f = CLK_HZ/(2*div)`；`div` 由 `CLK_HZ/(2*f_note)`
  （G4/C5/D5/E5/F5/G5/A5）在综合时算成常量。50MHz 下约

### 18.2 触发/保持/重臂语义（rev 2o 修正）

- **rev 2n 的错误**：最初接的是 tracker `out_stable`（10 帧锚点窗口
  内静止才置位）。运动球即使每帧都被识别，也永远满足不了 16px 锚点，
  可能整段运动都不触发。

  （EVT = tracker `out_valid`：首帧有效检测/候选即置位，并在 tracker
  自身 4 帧有界 hold 期间保持；CCL = `S_ccl_det_valid`）。不再使用
  `out_stable`。
- **hold 不假装新检测**：hold 只让 `O_det_valid` 保持高，不产生新的
  上升沿；播放器的边沿检测不会把 hold 当成一次新检测，也不会
  重启/叠加。
- 该电平从 CSI 域进入 50MHz 域时用 **2FF 同步器**，再取上升沿；
  note/序列/重臂计时全部在稳定 50MHz 域。SDC 的
  `set_clock_groups -asynchronous` 已把 MIPI_RX_BYTE_CLK 与
  sys_clk_50m 分开，无需新增 false path；最终 `check_timing` 中没有
  `u_two_tigers` 跨域路径。仿真实测 CSI 上升沿到 start 约 2 个
  50MHz 周期。
- 上升沿 + `armed` + `!playing` 才启动一首；启动后 `armed=0`；
  播放中忽略任何新上升沿/丢帧/hold，不重启、不叠加。
- 一首 16s 播完 `playing=0`、输出 0；目标仍在也不自动重播（没有新的
  上升沿，armed 保持 0）。
- 目标消失（`O_det_valid=0`，即 hold 到期后）持续 **1s** 后 `armed=1`；
  之后目标重新出现的上升沿才再次启动。短暂丢检/hold（<1s）不会重臂，
  避免闪烁反复。
- 播放中若目标消失 >1s，`armed` 可置 1，但当时上升沿被 playing 忽略；

- `O_buzzer` 约束 **C12**（LVCMOS33，8mA）；`pin.adc` 原先无 C12，
